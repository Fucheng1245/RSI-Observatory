# Launch Checklist

RSI Observatory is designed to launch as a **finished product**, not an empty placeholder.

## GitHub repository

**Repository name**

`RSI-Observatory`

**About / description**

> An evidence-driven living map of Recursive Self-Improvement — systems, scorecards, benchmarks, papers, safety and live project momentum.

**Recommended topics**

`recursive-self-improvement` · `rsi` · `self-improving-agents` · `self-evolving-agents` · `ai-agents` · `ai4ai` · `automated-ai-research` · `agent-evaluation` · `ai-safety` · `llm-agents`

## Before announcing

1. Push the full repository, including `assets/`, `data/`, `docs/`, `radar/`, `scripts/` and `.github/`.
2. Run **Update RSI Observatory** once from Actions so self-links normalize and the first dated snapshot is stored.
3. Enable **GitHub Pages → Deploy from branch → main → /docs**.
4. Upload `assets/social-preview.png` as the GitHub repository Social Preview image.
5. Confirm README dynamic blocks still render after the updater.
6. Confirm the Pages Scorecard and Radar load `data.json` and `scorecard.json`.
7. Pin an issue inviting classification corrections — this signals that the Scorecard is evidence-driven rather than arbitrary.

## First public post

Lead with the differentiation, not the catalog size:

> **RSI Observatory** is a living map of Recursive Self-Improvement. It combines a complete field map with an evidence-based RSI Scorecard, benchmark guide, live GitHub momentum, safety tracking and a weekly Radar. The goal is to answer not only “what exists?” but “what actually counts as RSI, how strong is the evidence, and what is changing now?”

Then show one visual artifact: **the Scorecard** or **the live Radar**.

## Weekly operating rhythm

- **Daily:** automated repository + paper data refresh.
- **Monday:** automated `RSI Radar — YYYY-Www` snapshot.
- **During the week:** curate only genuinely important changes into the Scorecard / Landscape.
- **Monthly:** review stale projects, classification disputes and benchmark changes.

## Star strategy

Do not ask people to Star because the list is “comprehensive.” Ask them to Star because the Observatory is useful again next week.

The recurring reasons to return are:

- 7-day project momentum;
- new executable RSI systems;
- benchmark changes;
- scorecard reclassifications;
- weekly high-signal Radar.
